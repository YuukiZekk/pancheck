# 方案：115 低质筛面板（基于 sieve.py）

一句话：把这次手工排除低质的**需求口径**和**操作流程**原样搬进一个带界面的面板，内核直接用 `sieve.py`，给别人装上填自己的路径就能用。

## 一、我的需求（这次实际用的口径，不多不少）

**判定（按这次实际排查的先后顺序；打 ✓ 的已在 sieve.py 里逐行验证过）**
- **REMUX 区排查（最开始的那轮）**：全区盘点到单元级 → 按 Emby 库分三类：已有原盘 / 疑似 / 未见
  - 已有原盘的再分层：T1 明牌低质、T2 体积存疑、T3 同档冗余 → 分批出清单
  - 未见的先做区内互重（同片多份留一），再跟原盘区交叉比
  - 无视频壳（只有 .nfo/字幕的空夹）单列一类
- **REMUX × 原盘交叉**：A 真低质 / B 同档冗余 / C 同内容冗余 → 可切；D 待定（原盘份悬殊、档位存疑分三小类）；E REMUX 更高档 → 不动
- **原盘区精确重复**：同片同规格的精确重复，扣掉保护区和保留规则后才可动；拿不准的进 hold 名单逐项核
- **合集区三刀 ✓**：第一刀 合集 × 原盘（档低/同档可切，DIY×普通两边留，档未知待定）；第二刀 区内互重留最优（版本型待定，剧集塌缩守卫整组挂起）；第三刀 小文件层（有原盘正经份/库内份可切）
- **纵向 ✓**：剩余片 × Emby 库 — 比库里好出洗版提醒、库里没有出入库提醒（只认 TMDB 精确，疑似只标注）
- **电视剧分流**：电影区里混入的剧集不进排查区，单独列清单搬去电视剧区归档（系列电影合集内的除外）
- 孤本永不进可切

**保留规则**
- 原盘区 > 合集区；DIY/特效字幕 > 普通原盘 ISO > REMUX > 小文件
- 带配置说明、刮削过的优先留；纯片名裸名不当保留份

**保护（写死逻辑，用户只能加不能绕）**
- 保护区：系列合集、出品公司、已刮削区（用户配置具体目录名）
- 榜单包（豆瓣/IMDB/戛纳类完整性收藏）不筛不拆
- 金庸/动漫/剧集类包默认排除，单独处理

## 二、我的操作（面板流程就照这个顺序）

1. **连数据源**：填 CloudDrive2 路径 + Emby 路径 → 自动找到 `dir_cache.sqlite` 和 `library.db`，回显识别结果（库规模、电影数）让用户确认找对了
2. **勾选盘点范围**：缓存目录树里勾要筛的文件夹（合集区/原盘区/REMUX 区各对应哪个目录，模板预置、用户可改）
3. **跑筛**：一键跑完六个筛类，进度可见；结果分类列出：可切 / 待定 / 版本型 / 孤本 / 提醒，每类带数量和体积
4. **看清单审**：逐条看候选（路径、大小、档位、保留份是谁、判定依据），可勾掉不想动的；**只有可切类能被批准**，待定和孤本没有执行入口
5. **执行**：批准后才搬，统一搬进「排查区」（用户配置目录），**只搬不删**，删除永远用户自己在网盘里做
6. **对账**：搬完自动对账 — 清单数 = 搬成 + 跳过（源已不存在）+ 失败（逐条列名）；对不上不算完成
7. **回滚**：凭搬运日志一键搬回（核对文件身份，不覆盖）

## 三、面板构成（最小集）

| 页面 | 内容 |
|---|---|
| 设置 | CD2/Emby 两个根路径、保护区与榜单包目录名、排查区目录、合集/原盘/REMUX 区映射 |
| 盘点 | 目录树勾选、库存概览（片数/体积/分区） |
| 筛选 | 跑筛按钮、三刀 + 纵向结果总览（数量/体积/占比） |
| 清单 | 分刀分级列表、搜索过滤、逐条依据、勾选批准 |
| 执行 | 搬运进度、逐条结果、对账报告、回滚 |

后端：Python + FastAPI，内核 `sieve.py` 直接 import（纯标准库函数，无框架依赖）；三刀+纵向已验证，REMUX 三分分层、交叉筛、原盘精确重复、剧集分流按同一套写法补进内核（这次实操的脚本都在，逐个收编+对金标准）。搬运走 CloudDrive 挂载目录的同盘 rename。前端：单页轻界面，不上重框架。分发：Docker（amd64/arm64）。

筛选页的结果分类按排查对象组织：REMUX 区（三分+分层）、交叉、原盘重复、合集三刀、纵向提醒、剧集分流 — 每类都是同一套「清单 → 批准 → 搬 → 对账」。

## 四、红线（这次实操换来的，写进代码不靠自觉）

- 代码里**没有删除调用**，只有搬移；删除归用户
- 未经清单批准**没有执行入口**；改配置后旧清单自动作废、必须重跑重批
- 保护区/榜单包在判定层排除，配置改错也整批拒绝，不部分执行
- 整夹搬运前验**单元纯度**（夹内只含该片文件才许整夹；多片夹逐文件搬）— 成龙夹事故的教训
- 对 CD2 缓存和 Emby 库**永远只读**打开

## 五、分期

- **第一期（先能用）**：设置 + 盘点 + 跑筛 + 清单导出（只读，不带执行）— 内核已验证，这期主要是适配层和界面
- **第二期**：批准 + 执行 + 对账 + 回滚

## 六、使用环境

**开发环境（本次就这么定）**
- 在 **Windows** 上开发（由 Claude 在 Windows 本机执行），**没有内网环境**：开发机连不到 CloudDrive2 / Emby 所在的内网
- 所以开发期不接真库：用导出的样例数据开发调试（片级 CSV + 一份 CD2 缓存 SQLite 副本 + 一份 Emby library.db 副本，拷到开发机本地即可）；真实路径只在部署到用户机器时才在设置页填入
- Python **3.12**，项目自带虚拟环境（见下），不要往系统 Python 里装东西

**虚拟环境（要，项目级 .venv）**
- 在项目根目录建：`py -3.12 -m venv .venv`，之后所有依赖只装进 `.venv`（`fastapi`、`uvicorn`，内核 sieve.py 是纯标准库、零依赖）
- 依赖清单固定在 `requirements.txt`；附 `setup.ps1` 一键建环境装依赖、`start.ps1` 一键启动 — venv 必须在 Windows 本机建，Linux 上建的带不过去

**终端用户运行环境（两种，二选一）**
- Windows 直接跑：Python 3.12 + 项目 .venv + `start.ps1`，面板默认只绑 `127.0.0.1`（端口如 8760），本机浏览器打开；要局域网访问自己改绑定
- Docker：amd64/arm64 镜像，适合常驻 NAS/服务器的用户
- 运行机需要能访问：CloudDrive2 的缓存目录与挂载目录、Emby 的 data 目录（只读）
