# 反馈 7：CD2 直连认不出真实的 api_tokens.json 格式（真库实测）

新版（5fce89d）部署到 fn 真库后实测：exec/status 一直报 backend=mount、direct=null，直连没生效。定位到令牌识别这一处：

## 事实

CD2 的 `api_tokens.json` 真实格式是 **{ 令牌本体: {元数据} }** —— 顶层键就是令牌字符串，值是元数据（friendly_name / root_dir / permissions / expires_in 等）。用户库里有 3 个令牌（名分别为 sa、salocal、Muse），全是这个结构。

`panel/cd2api.py` 的 `_token_candidates` 只在 dict 里找 `token` / `Token` 字段，真实文件里没有这种字段，于是返回空 → auto 模式静默落到挂载后端。

## 修法

`_token_candidates` 增加对真实格式的识别：

- 顶层 dict 的键，若值是含 `friendly_name` / `permissions` 等元数据的 dict，该键本身即为令牌候选。
- 挑令牌时可参考元数据：优先 permissions 里 `allow_move` 为真的；有多个时优先 friendly_name 与用途相符的，或全部作为候选依次试连（connect 成功为准）。
- 现有两种来源（环境变量 CD2_API_TOKEN、文件里的 token 字段）保留。

## 临时绕行（已验证可用，不用等修复也能测）

把令牌经环境变量 `CD2_API_TOKEN` 注入容器后，直连立即生效（status 显示 backend=cd2、direct ok、root=/）。真库实测数（批次 B20261111-123643，对账 3 = 搬成 3 + 跳过 0 + 失败 0 + 拒绝 0，平齐）：

| 操作 | 体积 | 搬移耗时 |
|---|---|---|
| 魔偶奇谭：至小帝国（文件夹） | 39.2 GB | 22.2 秒 |
| 正义联盟：新的边际（单文件） | 9.1 GB | 21.0 秒 |
| 超人与蝙蝠侠：公众之敌（单文件） | 9.9 GB | 13.8 秒 |

耗时与体积无关（39 GB 与 9 GB 同量级），证明是服务端改名、无数据传输；每部固定约 15–20 秒，是 CD2 接口本身的单次调用成本。对比挂载模式的 41–98 秒/部，直连快 4–5 倍，与手工 `clouddrive mv` 通道（约 12 秒/部）同量级。预演在直连下 3 条用 25 秒（挂载模式约 10 秒/条以上），也有改善。
