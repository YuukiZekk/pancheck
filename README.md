# sieve 筛选面板

115 网盘影视低质筛选面板。内核是 `sieve.py`（原样未改），面板只是适配层 + 界面。

**当前版本：设置 → 盘点 → 筛选 → 清单导出，全程只读。** 只出清单，不会移动、改名或删除任何文件。
默认直接读 CloudDrive2 自己的目录缓存（`dir_cache.sqlite`），盘点不向网盘发请求。

## NAS 上用 Docker Compose 部署

```bash
mkdir sieve-panel && cd sieve-panel
curl -fsSLO https://raw.githubusercontent.com/YuukiZekk/pancheck/main/docker-compose.yml
# 打开 docker-compose.yml，只改 volumes 里标出的两行路径，然后：
docker compose up -d
```

镜像是预构建的（`ghcr.io/yuukizekk/pancheck`，amd64 / arm64），不用在 NAS 上编译。浏览器打开 `http://<NAS-IP>:8760`，第一次打开会进入三步向导。

**要改的只有两行**（`docker-compose.yml` 的 volumes 里有箭头标出）：

| 哪一行 | 填什么 |
|---|---|
| CD2 配置目录 | 装 CloudDrive2 时，映射到它容器里 `/Config` 的那个宿主机目录 |
| Emby 数据目录 | 装 Emby 时，映射到它容器里 `/config` 的那个宿主机目录 |

**怎么找这两个路径：**

- **CD2**：打开你当初装 CD2 的 compose 文件或容器设置，看「存储空间 / 卷」里哪个宿主机目录对应容器的 `/Config`，就是它。
- **Emby**：Emby 后台 → 设置 → 关于（或「日志」页）能看到程序数据路径（容器里一般是 `/config`）；再到 Emby 容器的卷设置里，看哪个宿主机目录对应它。
- **群晖（DSM）**：Container Manager → 容器 → 选中 CD2 / Emby → 详情 →「存储空间设置」，左列就是宿主机路径，常见形如 `/volume1/docker/clouddrive2/config`、`/volume1/docker/emby/config`。
- **飞牛（fnOS）**：Docker → 容器 → 选中 CD2 / Emby →「存储位置」，常见形如 `/vol1/1000/docker/clouddrive2/config`。

（截图稍后补。）目录填到上一级也行，面板会自己往里找数据库；填错了向导会用人话告诉你差什么。

`.env` 是可选的，只在想设访问口令（`PANEL_PASSWORD`，**建议设**）或改端口时才建：

```bash
curl -fsSL https://raw.githubusercontent.com/YuukiZekk/pancheck/main/.env.example -o .env
```

外部目录全部 **只读** 挂进容器；面板自己的配置和结果在 `./data`。老版本的 `.env`（`CD2_CONFIG_HOST` / `EMBY_DATA_HOST`）照旧生效。

常用管理：

```bash
docker compose logs -f sieve-panel           # 看日志
docker compose pull && docker compose up -d  # 更新到最新版
docker compose down                          # 停止
```

## 使用流程

1. **首次设置向导**（三步，每步识别完给出验收数字，对得上再点下一步）：
   - 连 CD2：自动找目录缓存，显示缓存时间、115 文件数、顶层目录；缓存里有多个网盘时才让你选。
   - 连 Emby：自动找 library.db，显示电影数；自动推断 Emby 路径前缀并请你确认（strm 镜像库会说明不用设）。
   - 确认分区与保护：按目录名建议合集 / 原盘 / REMUX / 整夹合集，按模板预勾保护目录，显示缓存覆盖情况。完成后直接进盘点。

   之后「设置」页顶部是 CD2 / Emby 两张已识别卡（可「更换目录」），其余参数在「高级设置」里，一般不用动。
2. **盘点**：分区随时可以在目录树里改（下拉框绑定分区、🔒 加保护），然后「盘点」。
3. **筛选**：点「开始筛选」，跑错了可以随时点「停止」。结果分成下面几类：

   | 分类 | 是什么 | 能不能动 |
   |---|---|---|
   | 可清理 | 别处已有同一部片、画质更好或相同的副本，这份删了不会丢片 | 可移走（后续版本） |
   | 需人工确认 | 规则拿不准（画质没标注、体积对不上），请逐条判断 | 先别动 |
   | 不同版本 | DIY/特效字幕版与普通版，或剪辑版本不同 | 不要动 |
   | 这份更好 | 合集里这份比原盘区那份画质更高 | 不要动 |
   | 唯一副本 | 全库只有这一份 | 不要动 |
   | 主库缺口 | Emby 片库（主库）里没有这部片，可挪进主库补缺 | 可挪入主库（第二期） |
   | Emby 片库对比 | 主库已有：库里版本更差的建议洗版，同档或更好、片名疑似的仅标注 | 仅提醒 |
   | 混入的剧集 | 电影区里混进来的电视剧 | 仅提醒 |

   导出的 CSV 最后一列「内部分类」保留了内核叫法（可切/第一刀/A 等），方便和金标准对账。
4. **清单**：按分类、来源、关键字过滤，逐条看保留份和依据；导出 CSV 或全部 zip。


## 执行（第二期：只搬不删）

默认关闭，面板保持只读。要执行，两道开关都要开：

1. `docker-compose.yml` 里 CD2 挂载那行 `:ro` 改成 `:rw`，`.env` 里填 `CD2_MOUNT_HOST`（CD2 在宿主机上的挂载根）；
2. `environment` 里加 `PANEL_ALLOW_MOVE=1`，`docker compose up -d` 重建。

然后在设置 → 高级里填三个去处（都要和片子在同一个网盘里，同盘改名是秒搬）：排查区、主库目录、唯一副本目录。

流程：

- **批准**：在「清单」里勾选「可清理」（→ 排查区）或「主库缺口」（→ 主库）后点「批准」。同时是「唯一副本」的缺口，去处由你选。设置一改，批准自动作废。
- **预演**：「执行」页点「预演」，实时检查整夹纯度、目标冲突、是否同盘，不动文件。夹里只有这一部片才整夹搬（连 nfo / 字幕），混装夹只搬那个文件，多片夹不许整夹。
- **执行**：确认时要输入搬运处数。排查区按批次建子目录、保留原路径。每处先写日志再动手；只用改名，跨盘或失败不会退回复制；没有任何删除。
- **对账**：每批跑完自动核对：批准数 = 搬成 + 跳过（源已不在）+ 失败 + 预演拒绝，逐条点名，实地核对源没了、目标在。
- **续跑 / 回滚**：中途崩了按日志续跑；回滚按日志搬回原位，体积对不上的不覆盖、报出来。
- **试跑门槛**：第一次只许 ≤10 条，对账无误后才放开批量。

## 写进代码的红线

- 没有任何删除、移动、改名调用；第一期没有执行入口。
- CD2 缓存 / Emby 库以 SQLite 只读模式打开（打不开时拷快照到 `data/snapshot` 读副本）。
- 保护目录名按目录组件匹配（任意层）；榜单包只认「包」这一层（分区根下第一级目录），更深层目录名里顺带的「豆瓣8.1」「戛纳影帝」不算。保护区在提取时剔除其下全部条目；榜单包留在合集人口里（与金标准同口径），由内核判定层整包不筛，用户追加的榜单包名由面板在结论里排除。可切里仍有任一命中则整批拒绝、可切类不许导出。文件名和「单片夹」夹名里的简介字样（如「豆瓣9.1分」）不算命中——单片夹指夹内只直接放着同一部片、且夹名含该片名的目录。
- 设置改动后旧结果自动过期（按配置指纹判断），「可清理」必须重新筛选才能导出。
- 合集区按手工口径分出剧集：只认文件名里的 SxxExx 和「第N集」，裸 EP01、第N话等不分出（同一文件夹里有 2 个以上时，仍会在「混入的剧集」里列为疑似提示，不出人口）。
- 内置的榜单/排除词不可删除；删除已有保护目录名需要显式勾选确认。

## 数据来源三种模式

- **读 CD2 目录缓存**（默认，推荐）：直接读 `dir_cache.sqlite`（只读），按网盘标识过滤（115 是 `115open`，同一网盘多账号时可再填账号标识），生成内核要的五张 CSV。几十万个目录也是秒级，**不向网盘发任何请求**。
  - 结果以**缓存时刻**为准：CD2 没打开过的目录不在缓存里，缓存之后新增/删除的文件也看不到。结果页会显示本次用到的缓存时间范围。想更新就先在 CD2 里把相关目录打开刷新一下，再重新筛选。
  - 和遍历挂载目录的结果逐条一致（同一份数据下生成的 CSV 逐字节相同）。
- **遍历 CD2 挂载目录**（兜底）：缓存不可用时才用。大库首跑很慢，而且每个目录都会经 CD2 向网盘发请求，有风控风险。不会自动切换到这个模式，需要你在设置里手动选。
- **CSV 模式**：把 `yuanpan_units.csv`、`yuanpan_files.csv`、`emby_yp.csv`、`heji_films.csv`、`emby_titles.csv` 放进 `data/csv/`，直接喂内核。适合用已验证过的金标准数据复核。

## 当前已知边界

- 已接入：第一刀、第二刀、第三刀、纵向轴（内核已对金标准验证），剧集分流（新写，**未对金标准**，仅出清单）。
- 已接入「合集 × REMUX」（A1，口径 = cross_remux.py，422 对逐对对上，`tools/verify_a1.py`）：合集区影片和「整夹合集区」单元（如 10-合集）对 REMUX 区同一部片比档位；档低/同档 → 可清理（合集那份），DIY 与普通版 → 不同版本，合集更好 → REMUX 那份需人工确认，画质推断不出 → 需人工确认。已被三刀判可清理的不重复列。
- 「整夹合集区」：按单元（直接放着视频的文件夹）只参加跨区比对，不进三刀，不影响第一期基线。
- 已接入「原盘完全重复」两层（A2，`tools/verify_a2.py`）：
  - 第一层：原盘区同名同大小、放在不同文件夹的文件（盘片夹按夹名 + 总大小）。数据包上可移 84 条与 moves5 逐条一致。
  - 第二层：内容完全相同但改了名的文件（缓存模式按 Sha1，遍历模式按字节数），跨分区查；保留份按 build16b 计分（规格标注全、已刮削、带 tmdb、原盘区优先；裸名不当保留份）。数据包上 1,176 组逐组一致。
  - 保留档：保护目录 + 榜单包 + 内置「系列电影合集 / 出品公司 / 原盘已刮削」+ 设置里追加的「优先保留目录」。保留档只决定留哪份，**不会**把目录从比对人口里剔除——所以不用为 A2 往保护名单里加系列，第一刀基线不受影响。
  - 剧集、碟内文件、另议包（金庸 / 动漫 / ADWEB）不搬也不当保留份；已被其他模块判可清理的不重复列。
- 已接入「REMUX × 原盘」（A3 交叉，口径 = cross_screen.py，`tools/verify_a3.py` 1,395 对逐对一致）：REMUX 区和整夹合集单元对原盘区同一部片比档位，原盘那份只当参照。原盘 4K × REMUX 低档、双 4K、双 1080p → REMUX 那份可清理；任一侧画质看不出 → 需人工确认；REMUX 更高 → 不列。
- 未接入：REMUX 分层（A3 第二件，按 Emby 片库分已有原盘 / 疑似 / 未见再分 T1–T3）。
- 缓存/遍历模式生成的 CSV 口径是按目录结构推断的（BDMV/VIDEO_TS 夹按一张盘计、合集「大包」= 分区下第一级目录），和手工导出的 CSV 可能有出入，首跑建议用 CSV 模式对一遍数。
- Emby 新版 `MediaItems.type` 若是数字，电影按「非剧集、非文件夹」推断，识别页会提示，请核对数量。

