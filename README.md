# sieve 筛选面板

115 网盘影视去重面板：把同一部片在各分区的副本找出来归成一组，说清留哪份、哪份可以清，点完就能执行。

**默认只读：** 不开启执行时只出清单，不会移动、改名或删除任何文件。开启执行后可搬移——只搬不删、可对账、可回滚。
默认直接读 CloudDrive2 自己的目录缓存（`dir_cache.sqlite`），扫描不向网盘发请求。

## NAS 上用 Docker Compose 部署

```bash
mkdir sieve-panel && cd sieve-panel
curl -fsSLO https://raw.githubusercontent.com/YuukiZekk/pancheck/main/docker-compose.yml
# 打开 docker-compose.yml，只改 volumes 里标出的两行路径，然后：
docker compose up -d
```

镜像是预构建的（`ghcr.io/yuukizekk/pancheck`，amd64 / arm64），不用在 NAS 上编译。浏览器打开 `http://<NAS-IP>:8760`，第一次打开会进入三步向导。

**要改的只有两行**（`docker-compose.yml` 的 volumes 里有箭头标出）：

| 哪一行 | 填什么 |
|---|---|
| CD2 配置目录 | 装 CloudDrive2 时，映射到它容器里 `/Config` 的那个宿主机目录 |
| Emby 数据目录 | 装 Emby 时，映射到它容器里 `/config` 的那个宿主机目录 |

**怎么找这两个路径：**

- **CD2**：打开你当初装 CD2 的 compose 文件或容器设置，看「存储空间 / 卷」里哪个宿主机目录对应容器的 `/Config`，就是它。
- **Emby**：Emby 后台 → 设置 → 关于（或「日志」页）能看到程序数据路径（容器里一般是 `/config`）；再到 Emby 容器的卷设置里，看哪个宿主机目录对应它。
- **群晖（DSM）**：Container Manager → 容器 → 选中 CD2 / Emby → 详情 →「存储空间设置」，左列就是宿主机路径，常见形如 `/volume1/docker/clouddrive2/config`、`/volume1/docker/emby/config`。
- **飞牛（fnOS）**：Docker → 容器 → 选中 CD2 / Emby →「存储位置」，常见形如 `/vol1/1000/docker/clouddrive2/config`。

（截图稍后补。）目录填到上一级也行，面板会自己往里找数据库；填错了向导会用人话告诉你差什么。

`.env` 是可选的，只在想设访问口令（`PANEL_PASSWORD`，**建议设**）或改端口时才建：

```bash
curl -fsSL https://raw.githubusercontent.com/YuukiZekk/pancheck/main/.env.example -o .env
```

外部目录全部 **只读** 挂进容器；面板自己的配置和结果在 `./data`。老版本的 `.env`（`CD2_CONFIG_HOST` / `EMBY_DATA_HOST`）照旧生效。

常用管理：

```bash
docker compose logs -f sieve-panel           # 看日志
docker compose pull && docker compose up -d  # 更新到最新版
docker compose down                          # 停止
```

## 使用流程

一条主线：**设定 → 扫描 → 决定 → 执行**。每个页面顶部都有这条步骤条，标着现在在哪一步、下一步去哪。

1. **设定**（首次设置向导，三步，每步识别完给出验收数字，对得上再点下一步；一次设好，平时不来）：
   - 连 CD2：自动找目录缓存，显示缓存时间、115 文件数、顶层目录；缓存里有多个网盘时才让你选。
   - 连 Emby：自动找 library.db，显示电影数；自动推断 Emby 路径前缀并请你确认（strm 镜像库会说明不用设）。
   - 确认筛查范围：上面三个位置设一次，下面一棵目录树只管勾选。都按名字预选好，扫一眼没问题就点完成
     （按钮上带摘要，如「完成：筛查 5 个目录、排除 6 处、三位置已定 → 去扫描」）。
     - **主媒体库**：最终收藏所在；同一部片同档时，最优先留这里的那份。按名字猜（含「媒体库 / 主库」，或唯一的原盘区）。
     - **查重区**：筛出的重复份搬到这里，等你过目再删；它和下面都不扫。按名字猜（含「查重 / 排查」）。
     - **待入库区**：排重后留下、主库还没有的片挪到这里，等你放进主媒体库。带开关：关 = 留下的片留在原地、不搬。
       按名字猜（含「待入库 / 待整理 / 新入库」）。
     - **目录树**：勾上的参与筛查；勾父目录整枝生效，枝里不想筛的单独取消，任意层级都能展开。**没勾 = 不筛**——
       保护目录、榜单包不再单独设：系列电影合集、出品公司、已刮削大包、Top250 这类包在预选里就是「父级已勾、它们没勾」。
       网盘顶层全部列出；内容未知（CD2 没打开过）、部片太少、按规则隐藏的写灰字说明，只是提示，不挡勾选。
       勾上的目录按名字自动归类（原盘 / REMUX / 合集），只影响同档时先留哪份，界面上不用管。
     - 老配置第一次进这一步：已绑的分区原样当「勾上」，原来按名字的保护换成具体目录的「没勾」；点完成后按名字的保护不再单独生效。

   之后「设置」页顶部是 CD2 / Emby 两张已识别卡（可「更换目录」），其余参数在「高级设置」里，一般不用动。
   要改筛查范围，在「扫描」页最下面点「改筛查范围」，回到同一棵树，保存后重新扫描。
2. **扫描**：一个按钮，读一遍各分区和 Emby 片库、把同一部片的副本归组、出清单。扫完自动落到清单页。
   跑错了可以随时点「停止」。只出清单，不动任何文件。
3. **决定**（清单页）：每条写着这份是什么、留的是哪份；点开能看到这部片的全部副本（保留 / 也留 / 可清理 / 需人工确认 / 不碰）。
   结果分成下面几类：

   | 分类 | 是什么 | 能不能动 |
   |---|---|---|
   | 可清理 | 别处已有同一部片、画质更好或相同的副本，这份移走不会丢片 | 可批准搬到查重区（只搬不删） |
   | 需人工确认 | 规则拿不准（有一边分辨率看不出），请逐条判断 | 先别动 |
   | 不同版本 | DIY（加了中文字幕等）与原版，两份都留 | 不要动 |
   | 唯一副本 | 小体积 / 低画质，但全库只有这一份 | 不要动 |
   | 主库缺口 | Emby 片库（主库）里没有这部片，排重后留下的这份等着入库 | 批准后挪入待入库区（只搬不删；开关关着就留在原地） |
   | Emby 片库对比 | 主库已有：库里版本更差的建议洗版，片名疑似的仅标注 | 仅提醒 |
   | 混入的剧集 | 电影区里混进来的电视剧 | 仅提醒 |

   按分类、类别（重复副本 / 主库对比 / 孤本 / 剧集分流）、标签、关键字过滤（关键字同时搜候选路径和保留份路径），
   可按大小 / 名称 / 路径排序；导出 CSV 或全部 zip。每行片名下只有一个短标签，完整依据点开详情看。

   「需人工确认」看过、决定留着的，在详情里点「确认保留，以后不再提醒」（或勾选后批量点「确认保留」）。按路径记住，以后重新扫描不再出现在清单里，
   但不会悄悄消失：清单和总览会报「另有 N 条已确认保留，已隐藏」，全部 zip 里单独有一张「已确认保留（已隐藏）.csv」，设置页能看名单、逐条撤销。
   它只管「需人工确认」这一类，不影响判定，也不会让当前结果作废（和保护名单不同）。名单存在数据目录的 `keep_confirmed.json`。
4. **执行**：开启执行后，在清单里勾选、批准，右上角「去执行」进执行页预演 → 确认 → 对账（见下一节）。

### 重复副本怎么判

- **认片**：一个函数——TMDB 编号相同，或「片名 + 年份」相同。片名先挖掉字幕 / 版本 / 地区版 / 译制词和网站广告再取；
  同键的两份还要再核一次：一方名字最前面的中文片名要在另一方名字里出现（防发行商名比片名长时撞键）。
- **人口**：合集区每个影片文件；原盘区按片展开（盘片夹一份、一夹一部整夹一份、一夹多部逐文件一份）；REMUX 区 / 整夹合集区每个单元。
- **多碟装算一份**：同一个夹里并排放着、名字只差碟号的几个文件（Disc1/2/3、CD1/2、D1/D2、碟一/二、上/下集，ISO 连没写 Disc 的「片名 1 / 片名 2」也认），
  并成一套、体积加总，按一份参与比较，套内的碟永远不互相当副本。整套被判可清理时每张碟一行（标「多碟装」、写明第几张），要一起处理。
  碟号写在名字中段（…Disc2.1080p.AVC…）、或一张写碟号一张不写（…COLLECTION / …COLLECTION disc2）也认。
  只差 x264/x265、5.1/7.1、2Audio/4Audio 这类规格，或是下载重名的「(1) / (2)」的，不算一套。
  名字里写着 Disc / CD / 碟 几、却没和同套其他碟并上的（只剩半套，或同片两个版本各写了碟号），不自动判，进「需人工确认」。
- **保留份**：先比分辨率（4K > 1080p > 720p 及以下），同分辨率再比来源（特效字幕版 > 原盘 > DIY > REMUX > 压制），再比所在区（原盘区优先），
  再比命名（带 {tmdb}、在已刮削目录、规格写得全的优先；裸名靠后），最后比体积。分辨率：原盘区先看 Emby 实测，其次看主文件名，
  再按 ISO / 盘片夹体积推断（≥55 GB 为 4K，带 * 标注）；其他区看名字，名字没写的 ISO 同样按体积推断、普通文件 ≥40 GB 推断为 4K。
- **特效字幕版**：名字里写了「…特效…字幕」（简繁特效字幕、国配简繁英特效四字幕…），或命中设置里的「特效字幕组」名单
  （默认带号主确认的名单：SGNB、Thor@HDSky、雅典娜 / Athena@HDSky、x-man@HDSky、DIY@HDSky、Nest@ADWeb / Nest@ADE、Nimbus@Sunny、
  Breeze@Sunny、LINMENG@CHDBits、nn@CHDBits、sh@CHDBits、BHYS@OurBits、至尊宝、WCL碟影）。英文不分大小写、只认整段；中文名出现在片名里不算，
  写成发布标签（-雅典娜、雅典娜小组@…）的才算。清单里带「特效字幕」标记和「特效字幕版」标签，详情写明是凭字样还是凭名单哪一项认出的。
- **组内其余每份**：
  - DIY / 特效字幕版与原版是一对，两份都留（保留份不是这两类时，最好的一份 DIY / 特效字幕版也留；保留份是这两类时，最好的原版也留）；
    多出来的 DIY / 特效字幕版跟留下的那份比；
  - 剪辑版本不同（导演剪辑 / 加长 / 未分级 / IMAX…）的分开各自比；
  - 有一边分辨率看不出 → 需人工确认。例外：REMUX 没标分辨率、保留的是已确认（非推断）的 4K 原盘 / DIY → 可清理；
    两份都没标、来源相同 → 留更大的；没标分辨率的压制版对上已知分辨率的原盘 / DIY / REMUX → 可清理；小文件没标分辨率、保留的是正经版本 → 可清理；
  - 其余（分辨率更低或同档）→ 可清理。
- **不碰**：榜单包、排除词（金庸 / 动漫 / ADWEB 及设置里追加的）、一份里装着几部片（「红气球+白鬃野马」「三部曲」）的副本：可以当保留份，自己不进可清理。
- **挂起**：合集区里同一个夹有 ≥3 份、或 ≥2 份带集号的组，像剧集，整组不判，只在总览里报数。
- **标签**：与原盘重复 / 合集内重复 / 原盘区内重复 / 涉及 REMUX / 整夹合集 / 小文件低质 / 原盘同名同大小 / 同字节——清单里可按标签筛，不是流程关卡。
- 另外两条独立的线照旧：**原盘同名同大小**（原盘区同名同大小、放在不同文件夹）和**同字节**（内容完全相同但改了名，缓存模式按 Sha1），
  结果也归到「重复副本」，带各自的标签；已被前者判掉的不再进归组。

## 执行（只搬不删）

默认关闭，面板只出清单。执行动的是网盘里的真文件，所以要你自己把下面四步做齐：

1. **在 CloudDrive 里新建一个 API 令牌**，勾选这三项权限：列目录、建文件夹、移动（不要给删除权限）。
   面板会自己从 CloudDrive 的配置目录里读到它，不用复制粘贴；令牌只在内存里用，不写进配置、计划和日志。
2. **在 `docker-compose.yml` 的 `environment` 里加一行 `PANEL_ALLOW_MOVE=1`**，然后 `docker compose up -d` 重启面板。
3. **在设置页确认三项**：CD2 接口地址（形如 `192.168.1.50:19798`，即 CloudDrive 网页的地址和端口）、查重区、待入库区（首次设置第 3 步顶部已设的话不用再填）。
   唯一副本目录用到再填。这几个目录要和片子在同一个网盘里。
4. **打开「执行」页**：状态行会逐项告诉你还差哪一步，全齐了才会出现可用的执行按钮。设置页「执行」卡片里也能看到同一张清单。

执行方式有两种（设置页「执行」卡片里的「执行方式」，默认自动：找到令牌就用直连）：

- **直连（推荐）**：面板直接跟 CloudDrive 说话搬文件，快，一部几秒到二十秒，和体积无关。
  直连出错会停下并说明原因，**不会悄悄改用挂载**；续跑时由你选方式。
- **挂载**：经过系统文件夹改名，慢（一部 1–2 分钟），只在没有令牌时兜底。
  要把 compose 里挂载那行 `:ro` 改成 `:rw`，`.env` 里填 `CD2_MOUNT_HOST`。

流程：

- **批准**：在「清单」里勾选「可清理」（→ 查重区）或「主库缺口」（→ 待入库区）后点「批准」。同时是「唯一副本」的缺口，去处由你选。设置一改，批准自动作废。
  重新扫描时，上一轮的批准里「新结果里仍在、判定没变（分类 / 类别 / 判定 / 保留份都一样）、去处不变」的自动带过来，
  其余作废并逐条说原因；跑完报「上轮批准 N 条：带过来 M 条、已失效 K 条」。两轮之间改过设置则一律不带。带过来的批准在预演时照样全部复核。
- **预演**：「执行」页点「预演」，实时检查整夹纯度、目标冲突、是否同盘，不动文件。夹里只有这一部片才整夹搬（连 nfo / 字幕），混装夹只搬那个文件，多片夹不许整夹。
- **执行**：确认时要输入搬运处数。查重区按批次建子目录、保留原路径。每处先写日志再动手；只用改名，跨盘或失败不会退回复制；没有任何删除。
- **对账**：每批跑完自动核对：批准数 = 搬成 + 跳过（源已不在）+ 失败 + 预演拒绝，逐条点名，实地核对源没了、目标在。
- **续跑 / 回滚**：中途崩了按日志续跑；回滚按日志搬回原位，体积对不上的不覆盖、报出来。
- **试跑门槛**：第一次只许 ≤10 条，对账无误后才放开批量。

## 写进代码的红线

- 没有任何删除调用。执行入口默认关闭，需在部署配置中显式开启；未开启时只出清单。开启后也只搬你批准过的条目，保护区命中整批拒绝。
- CD2 缓存 / Emby 库以 SQLite 只读模式打开（打不开时拷快照到 `data/snapshot` 读副本）。
- 榜单包内置规则只认榜单组合词：豆瓣 / IMDb 后面跟 Top N 或「榜单」（豆瓣电影Top250、IMDB Top 250、豆瓣电影TOP50）、Top 250、
  戛纳 + 电影节 / 金棕榈 / 获奖…；「豆瓣8.3分」「豆瓣排名117」「IMDb 7.5」「戛纳影帝」这类评分 / 简介字样不算。设置里可追加名字，内置规则认错的可在向导里点「不算」。
- 保护目录名按目录组件匹配（任意层）；榜单包只认「包」这一层（分区根下第一级目录），更深层目录名里顺带的「豆瓣8.1」「戛纳影帝」不算。
- 查重区（设置、向导、扫描页三处同一份）和它下面的条目不进扫描。勾选模型下没勾的目录在提取时剔除其下全部条目，内置榜单包规则不再另外起作用（没勾 = 不筛，勾上的榜单包照常筛）。
  以下是没走过新向导的老配置的口径：保护区在提取时剔除其下全部条目；榜单包留在合集人口里（与金标准同口径），由内核判定层整包不筛，用户追加的榜单包名由面板在结论里排除。可切里仍有任一命中则整批拒绝、可切类不许导出。文件名和「单片夹」夹名里的简介字样（如「豆瓣9.1分」）不算命中——单片夹指夹内只直接放着同一部片、且夹名含该片名的目录。
- 设置改动后旧结果自动过期（按配置指纹判断），「可清理」必须重新扫描才能导出。
- 合集区按手工口径分出剧集：只认文件名里的 SxxExx 和「第N集」，裸 EP01、第N话等不分出（同一文件夹里有 2 个以上时，仍会在「混入的剧集」里列为疑似提示，不出人口）。
- 内置的排除词不可删除；删除已有保护目录名需要显式勾选确认。

## 数据来源三种模式

- **读 CD2 目录缓存**（默认，推荐）：直接读 `dir_cache.sqlite`（只读），按网盘标识过滤（115 是 `115open`，同一网盘多账号时可再填账号标识），生成内核要的五张 CSV。几十万个目录也是秒级，**不向网盘发任何请求**。
  - 结果以**缓存时刻**为准：CD2 没打开过的目录不在缓存里，缓存之后新增/删除的文件也看不到。结果页会显示本次用到的缓存时间范围。想更新就先在 CD2 里把相关目录打开刷新一下，再重新扫描。
  - 和遍历挂载目录的结果逐条一致（同一份数据下生成的 CSV 逐字节相同）。
- **遍历 CD2 挂载目录**（兜底）：缓存不可用时才用。大库首跑很慢，而且每个目录都会经 CD2 向网盘发请求，有风控风险。不会自动切换到这个模式，需要你在设置里手动选。
- **CSV 模式**：把 `yuanpan_units.csv`、`yuanpan_files.csv`、`emby_yp.csv`、`heji_films.csv`、`emby_titles.csv` 放进 `data/csv/`，直接喂内核。适合用已验证过的金标准数据复核。

## 当前已知边界

- 重复副本（上面「重复副本怎么判」）取代了早先按手工作业顺序分趟的几步（合集 vs 原盘、合集内重复、小文件低质、合集 vs REMUX、REMUX vs 原盘），
  数字和当年的金标准对不上是结构变了，对照见 `docs/基线.md`「旧类目 → 新结构」。`tools/verify_a1.py --legacy-keys`、`tools/verify_a3.py` 只复现当年手工口径，留作历史对照。
- 主库对比：合集区剩下的片和 Emby 主库比（库里没有 → 主库缺口；库里更差 → 洗版提醒；TMDB 对上、同档或更好 → 这份可清理；只片名对上 → 仅标注）；
  REMUX 区和整夹合集单元拿去比主库里的原盘版（主库那份不比这份差 → 可清理；REMUX 更高 → 提醒可给主库洗版；画质看不出或只有片名对上 → 需人工确认）。
- 剧集分流：新写，**未对金标准**，仅出清单。
- 缓存/遍历模式生成的 CSV 口径是按目录结构推断的（BDMV/VIDEO_TS 夹按一张盘计、合集「大包」= 分区下第一级目录），和手工导出的 CSV 可能有出入，首跑建议用 CSV 模式对一遍数。
- Emby 新版 `MediaItems.type` 若是数字，电影按「非剧集、非文件夹」推断，识别页会提示，请核对数量。

## 仓库里有什么

- `app.py`、`panel/`、`static/`：面板本体；`sieve.py`：片名键与主库对比的内核。
- `tools/`：演练（`drill_b.py`）、当年手工口径的对账（`verify_a1~a3.py`）、新旧片名键差分（`keydiff.py`，靠 `legacy_steps.py` 里的旧流程步骤）。
- `docs/`：`基线.md`（各轮基线，新基线用 `python -m panel.baseline` 打印）、方案、交接、任务单、前端方案；`docs/反馈/` 是历次反馈原文。
